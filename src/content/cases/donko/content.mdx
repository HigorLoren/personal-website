## O problema

Eu queria um app de Kanban simples, sem conta e sem servidor, que fosse meu para
usar e para mexer. As opções prontas não serviam: pediam login ou eram pesadas
demais para o que eu precisava. Construí o meu.

Com o tempo apareceu um segundo problema: manter um projeto vivo por anos
enquanto o ecossistema em volta muda inteiro.

## O que descobri

Um Kanban pessoal não precisa de backend. O estado cabe no navegador, e sem
servidor o app fica instantâneo e não custa nada para operar. Essa foi uma
decisão de produto, e é ela que mantém o Donko fácil de sustentar.

A cada dois anos a forma recomendada de construir uma SPA em React mudava. Passei
a usar o Donko como campo de treino: cada reconstrução é uma passada de
aprendizado no stack novo.

## O que construí

Três gerações do mesmo produto:

- **2021** — Create React App, JavaScript, Redux, animação com Framer Motion.
- **Reescrita** — Vite no lugar do CRA, TypeScript do começo ao fim, React Router
  no modelo novo, MUI e Tailwind juntos, i18n com i18next, formulários tipados.
- **React 19** — porte da base para a versão mais recente, para sentir na prática
  o que muda.

Para o usuário, as três versões fazem a mesma coisa. O que muda é a base.

## Resultado

O [app continua no ar](https://higorloren.github.io/donko), com o
[código aberto](https://github.com/HigorLoren/donko). É o projeto que mais mostra
constância: um produto pessoal que sigo mantendo, reconstruído sempre que o React
dá um salto.
